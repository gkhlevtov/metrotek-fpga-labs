# Задание №4 Инкремент байтов

## Описание

В данной лабораторной работе был верифицирован модуль инкремента байтов `byte_inc`, который прибавляет "1" к каждому байту на заданном участке памяти. Доступ к памяти осуществляется через два независимых интерфейса Avalon-MM, на которых модуль выступает мастером: только на чтение (`amm_rd_*`) и только на запись (`amm_wr_*`). Модуль также имеет управляющий интерфейс (`base_addr_i`, `length_i`, `run_i`, `waitrequest_o`), через который ему подаётся задание на обработку участка памяти.

Тестовое окружение реализовано с использованием объектно-ориентированного подхода: классы генератора, драйвера, мониторов, эталонной модели и скорборда объединены в тестовой среде. Поскольку DUT сам выступает мастером на обеих Avalon-MM шинах, тестовое окружение реализует модель памяти-слейва (`avalon_slave_model`), которая отвечает на запросы DUT.

## Структура проекта

```
task4/
├── rtl/                    # Исходный код верифицируемого модуля
│ └── byte_inc.sv
├── tb/                     # Тестовое окружение
│ ├── amm_ctrl_if.sv        # Интерфейс управляющих сигналов (base_addr, length, run, waitrequest)
│ ├── amm_rd_if.sv          # Avalon-MM интерфейс чтения
│ ├── amm_wr_if.sv          # Avalon-MM интерфейс записи
│ ├── byte_inc_pkg.sv       # Пакет с описанием классов
│ ├── byte_inc_tb.sv        # Верхний уровень тестбенча
│ ├── ctrl_item.sv          # Описание транзакции управляющего канала
│ ├── ctrl_monitor.sv       # Монитор управляющего канала, определяет границы задания
│ ├── driver.sv             # Драйвер для подачи заданий на управляющий интерфейс DUT
│ ├── environment.sv        # Контейнер для сборки всех компонентов
│ ├── generator.sv          # Генератор направленных и случайных тестовых сценариев
│ ├── golden_model.sv       # Эталонная модель, предсказывающая результат инкремента
│ ├── rd_item.sv            # Описание транзакции канала чтения
│ ├── rd_monitor.sv         # Монитор канала чтения, сохраняет порядок и тайминг ответов
│ ├── run.do                # Скрипт запуска симуляции
│ ├── scoreboard.sv         # Проверка захваченных транзакций относительно эталонной модели
│ ├── slave_model.sv        # Модель памяти (avalon_slave_model) для обеих Avalon-MM шин
│ ├── wr_item.sv            # Описание транзакции канала записи
│ └── wr_monitor.sv         # Монитор канала записи
├── README.md
└── report.md               # Отчет о найденных багах
```

## Инструкция по запуску симуляции

1. Перейти в директорию `tb`:
   ```
   cd tb
   ```
2. Запустить ModelSim и выполнить команду:
   ```
   do run.do
   ```
